# Automated Detection of AI-Generated Programming Solutions in Student Submissions

## Abstract

This study introduces a comprehensive approach for detecting AI-generated programming solutions by analyzing stylistic patterns and structural regularities in source code. The system quantifies variable naming, comment density, indentation consistency, repetition, and comment verbosity. The resulting metrics are combined into a composite score that distinguishes submissions with anomalous stylistic signatures from those that are likely human-authored.

## Introduction

The increasing availability of advanced code generation models has created new challenges for academic integrity in computer science education. Conventional plagiarism detection systems are designed to detect direct copying or structurally identical solutions, but they do not address the subtle stylistic artifacts that appear in machine-generated code. Code generated by artificial intelligence often exhibits a distinct combination of regular formatting, repetitive patterns, and verbose explanatory comments. This research aims to characterize those artifacts quantitatively and demonstrate how they can be used to flag suspicious submissions.

## Theoretical Framework

The proposed framework is based on the hypothesis that AI-generated code differs from student-authored code in measurable style dimensions. These dimensions include identifier naming, comment usage, indentation patterns, line repetition, and comment verbosity. Each dimension is represented by a feature function that maps a source file to a numerical score.

Let a source file be represented as a string of characters, and let the set of non-empty source lines be denoted by $L$. The feature functions are defined as follows.

### Variable Naming and Identifier Metrics

For a set of variable and identifier names $V = \{v_1, v_2, \ldots, v_n\}$, the average variable length is calculated as:

$$\text{avg\_var\_length} = \frac{1}{n + 1} \sum_{i=1}^{n} |v_i|$$

The denominator is offset by one to avoid division by zero when no identifiers are detected. The number of variables, $\text{num\_variables} = n$, provides a crude measure of program complexity and naming density.

### Comment Density

Comment density is defined in terms of the number of comment tokens $C$ extracted from the source text and the total number of source lines. It is computed as:

$$\text{comment\_density} = \frac{|C|}{|L| + 1}$$

For Python, comments are recognized using the line prefix '#'. For C-like languages, the system recognizes both single-line comments beginning with '//' and multi-line comment blocks enclosed by '/*' and '*/'.

### Indentation Consistency

Indentation consistency measures how uniformly the source code uses leading spaces. Given an array of leading space counts $I = \{i_1, \ldots, i_m\}$ for non-blank lines, the variance is:

$$\text{variance}(I) = \frac{1}{m} \sum_{j=1}^{m} (i_j - \mu)^2$$

where $\mu$ is the mean indentation. The consistency score is defined as:

$$\text{indentation\_consistency} = \frac{1}{1 + \text{variance}(I)}$$

This transformation maps low variance to values close to one, while large variance yields a score closer to zero. The design of this score emphasizes the characteristic regularity of AI-generated formatting.

### Repetition Score

Repetition is estimated by comparing the cardinality of the set of unique non-empty lines to the total number of non-empty lines. If $U$ is the set of unique lines and $|L|$ is the total number of non-empty lines, then:

$$\text{repetition\_score} = 1 - \frac{|U|}{|L| + 1}$$

A higher repetition score indicates that the code contains more repeated lines relative to its length, which may reflect template-like generation or repeated control structures.

### Comment Overexplanation

The overexplanation score measures the average comment length in words for all extracted comments. If the set of comments is denoted by $C$ and $\text{word\_count}(c)$ returns the number of words in comment $c$, then:

$$
\text{overexplanation\_score} =
\begin{cases}
\displaystyle \frac{1}{|C|} \sum_{c \in C} \text{word\_count}(c), & |C| > 0 \\
0, & |C| = 0
\end{cases}
$$

This metric captures the tendency of some AI-generated solutions to include verbose commentary that explains obvious operations.

### Composite Assessment

The system aggregates individual style features into a weighted sum, creating a final score that can be adapted for risk ranking. The general form of the composite score is:

Final Score = w_1 * StyleScore + w_2 * ComplexityScore + w_3 * LLMScore + w_4 * SimilarityScore + w_5 * SemanticScore

In the current analysis, the focus is on the StyleScore component. StyleScore itself is formed by combining the normalized feature values for indentation consistency, repetition score, comment density, average variable length, and overexplanation score.

## Implementation Details

The implementation consists of a feature extraction pipeline that supports Python and a set of C-like languages. For Python programs, the abstract syntax tree is parsed to extract identifier nodes and reduce the impact of literal content. For C-like languages, a heuristic parser identifies declarations of common types such as int, float, double, char, bool, long, auto, and string. String literals are removed from the source code before analysis in order to reduce false positives from textual content.

The feature extraction pipeline begins with a language-specific parser and proceeds to compute feature values from the source text. It then calculates indentation consistency, repetition score, and comment verbosity. The entire pipeline is designed to be robust to syntactically invalid code by falling back to lexical analysis when parsing fails.

## Dataset and Experimental Design

The dataset comprises a collection of student programming submissions across multiple tasks and languages. Each submission is associated with a student identifier and a filename. The evaluation framework reads each file, applies language detection based on file extension, and computes the full set of style features.

Exploratory data analysis includes visualization of feature distributions and the identification of statistical outliers. The use of an interquartile range rule provides a transparent means of flagging submissions that deviate from the majority. The lower and upper bounds are defined by:

$$\text{lower\_bound} = Q1 - 1.5 \cdot IQR$$
$$\text{upper\_bound} = Q3 + 1.5 \cdot IQR$$

where $Q1$ and $Q3$ are the first and third quartiles, and $IQR = Q3 - Q1$. Submissions with feature values outside these bounds are flagged for manual review.

## Empirical Results

The empirical evaluation demonstrates that stylistic metrics produce distinctive distributions across the corpus. Comment density often exhibits a long-tailed distribution, with a small subset of submissions containing exceptionally dense commentary. Indentation consistency generally clusters near higher values, while repeated-line structures show greater variance. Overexplanation scores reveal an interesting separation between concise, task-focused implementations and those with extended commentary.

Submissions that are flagged as outliers in multiple dimensions are particularly noteworthy. A submission that simultaneously exhibits high comment density, a high repetition score, and near-perfect indentation consistency presents a stronger signal of potential AI generation than a submission with only one anomalous metric. The conjunction of stylistic anomalies increases confidence in the assessment without relying on exact text matching.

## Discussion

The study confirms that style-based analysis can serve as a meaningful complement to existing academic integrity tools. The metrics developed here are not intended as definitive proof of AI authorship, but rather as indicators that guide further investigation. Style-based assessment is especially useful when source code is not directly comparable to known AI output or when the code has been substantially modified.

A potential limitation of the approach is the sensitivity of some metrics to the conventions of a particular task or codebase. For example, a difficult assignment requiring many repetitive constructs may naturally produce a higher repetition score even when the code is human-authored. Similarly, teams or classes that teach strict formatting styles can yield high indentation consistency scores for human submissions. These contextual factors necessitate careful calibration and the use of multiple features rather than a single score.

## Limitations and Mitigations

One limitation of the current system is its reliance on name- and comment-based heuristics for non-Python languages. The heuristic parser may misclassify identifiers in languages with unconventional syntax or in submissions that use macros and preprocessor directives heavily. To mitigate this, future versions should incorporate language-specific parsers and tree-based analysis for additional language families.

Another limitation is that the current framework does not directly compare semantic equivalence between submissions. It is therefore possible for two different authors to produce code with similar style if they follow the same template or stylistic guidelines. Combining style analysis with semantic similarity measures can reduce false positives and improve overall detection reliability.

## Conclusions

The extension of stylistic analysis to the detection of AI-generated programming solutions demonstrates a viable path for academic integrity monitoring. By formalizing the computation of feature scores and applying them across a corpus of student submissions, the system identifies anomalous artifacts consistent with machine-generated output. The use of explicit formulas and statistical outlier detection provides a transparent foundation for further research.

## Future Directions

Future research should integrate the style-based features with semantic and similarity-based models in a unified framework. The addition of supervised learning, trained on labeled examples of human and AI-generated code, would allow the system to learn more complex patterns than those captured by simple heuristics. There is also value in extending the analysis to additional languages and using deeper syntactic and semantic parsing for more accurate feature extraction.

A longer-term goal is to develop a real-time assessment tool that can support educators by ranking submissions according to the likelihood of AI assistance. Such a tool would enable targeted interventions while preserving confidence in authentic student work. The current results indicate that style analysis is a promising component of that broader solution.
